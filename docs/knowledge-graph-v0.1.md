# Knowledge Graph V0.1

## Scope

PandaWiki extracts a compact, structured graph from server-side node content
after the existing vector-upsert queue successfully processes a node. The
desktop client is a graph viewer only: it neither downloads a corpus nor runs
local embedding, entity extraction, or permission filtering.

## Data retained

- `graph_entities`: normalized entity name, type and knowledge-base scope.
- `graph_relations`: typed directed relation between two entities.
- `graph_evidence`: relation-to-node provenance, node release ID, and an
  excerpt capped at 512 characters.
- `graph_entity_summaries`: optional, source-node-scoped entity summaries
  produced during graph extraction.

The graph tables do not retain a full node body, a model prompt, or model raw
response. Reprocessing a node replaces that node's old evidence transactionally.

## Entity summaries

Entity summaries are generated by the server as part of asynchronous graph
extraction. They are derived from the sanitized graph projection rather than
being generated or assembled by a desktop client. A summary is stored per
source node, so the graph read can include only summaries whose source nodes
pass the same permission filter as graph evidence. The response therefore
contains only permission-filtered summary text; it never contains source
documents, prompts, or raw model output.

Existing graph facts do not receive summaries retroactively. After upgrading,
use **Rebuild graph from documents** for each applicable knowledge base (or
make a later update to an individual node) before source-scoped entity
summaries are generated.

## Permissions

`GET /api/v1/knowledge_base/graph?kb_id=<id>` requires normal PandaWiki login
and knowledge-base access. It derives the caller's group IDs on the server and
returns only evidence whose source node is currently `visitable` by that user.
Clients cannot submit `group_ids`.

## Queue behaviour

The existing vector `upsert` consumer invokes graph extraction only after RAG
upsert succeeds. A graph-model failure is logged with IDs only and does not
roll back vector indexing, node editing, or document reading. A later node
update retries graph extraction naturally.

## Client contract

The future `GraphProvider` consumes the endpoint above and renders entity and
relation data. Selecting a source opens the already-existing node-detail route.
It must not use local project paths or local graph-analysis code for a
PandaWiki virtual project.

## Self-hosted upgrade

Migration `000041_create_graph_entity_summaries` is applied by the API's normal
migration flow at startup. Do not run separate manual SQL for this upgrade.
Rebuild the images and recreate both the API and Consumer so the migration and
background graph-summary extraction are active:

```bash
cd /path/to/panda-wiki
git pull --ff-only
./deploy/scripts/build-images.sh
cd deploy
docker compose up -d --force-recreate api consumer
./scripts/healthcheck.sh
```

Keep the existing PostgreSQL, MinIO, Qdrant, and `.env` data directories. Once
the services are healthy, explicitly rebuild the graph for knowledge bases
whose existing facts should gain summaries.

## PostgreSQL repository integration tests

The permission and summary-persistence repository tests use a disposable schema
inside a real PostgreSQL database. They are excluded from normal `go test` runs
and skip when neither `DATABASE_URL` nor `POSTGRES_DSN` is set.

From `backend`, run them in PowerShell with:

```powershell
$env:DATABASE_URL='postgres://user:password@localhost:5432/pandawiki_test?sslmode=disable'; go test -tags=integration ./repo/pg -run 'TestGraphRepository' -count=1
```
